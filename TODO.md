# PROCESS

Work proceeds in delegated chunks (lettered below), each sized for one agent session and ending in a reviewable state: a branch with a focused diff, plus a short memo appended to `notes/LOG.md` stating what was done, what changed in outputs, what was verified, and open questions. Nothing merges to `main` without Colin reading the memo and diff; each merged chunk moves to DONE with the date and commit hash, so DONE doubles as an audit trail. Check-ins are weekly (~30 min): review the latest chunk, resolve open questions, and assign the next one. Two standing rules keep the project legible after time away: (1) no hard-coded numbers — every figure cited in `paper.Rmd` or `slides.tex` comes from a scalar CSV in `output/results/` written by an estimation script, and the full chain `derived/ -> program/ -> output/ -> paper.pdf` must rebuild via `make`; (2) a single spec sheet, `notes/specs.md`, records the exact estimating equation, sample restrictions, fixed effects, and clustering for every table and figure in the paper, and is updated in the same commit as any spec change. The paper text is checked against the spec sheet, not against memory.

Verification is built in rather than ad hoc. `program/tests/` holds fake-data tests run by `make test`: each estimator is applied to simulated data with known parameters (e.g., claims data with a built-in MH x post-1994 damage effect, common vintage effects, and geography-period shocks) and must recover the truth; the same harness demonstrates *why* the spec is right (e.g., that omitting common vintage effects biases the MH-vintage coefficients). Constructed denominators get the same treatment: any imputation must pass an exact adding-up test against its source totals and a fake-data test that recovers a known take-up gradient. Data-construction steps carry the standard sanity checks (uniqueness on intended IDs, cross-field consistency, missing-value accounting, counts validated against external benchmarks like Census 2000 MH counts and MHS shipments). Agent sessions run `make test` before opening a review; any red test blocks the merge. Review comments in `coarse-output/*_review.md` are the external checklist — each addressed comment gets flipped to `[Addressed]` in that file in the commit that addresses it.

## Chunk C1 — Fix specifications [agent; Colin reads diff]
Baseline-spec corrections to the NFIP claim-level design. **Run before D–G**: every downstream number moves, so landing this late means re-running the mechanism splits and the welfare table twice. All four changes are contained to `estimate-nfip.R`, `project-params.R`, and the Makefile call at line 51. Diagnostics below are from the 1988–1999 annual-bin sample, outcome `net_building_pmt` in $000s (2000).

Framing: the outcome is under-powered, but clustering is *not* the reason. There are 5,389 MH claims across 12 annual vintage bins (270–700 per bin) against ~205,000 site-built. The fixes below are (a) a defensibility fix and (b) three power fixes, in that order.

- [ ] **Cluster by county.** `feols(fmla_claim_es, ...)` at `estimate-nfip.R:246` passes no `cluster` argument, so fixest silently defaults to the first FE, `geo^year_loss`. That default permits arbitrary correlation within a county-loss-year but imposes independence across loss years within a county — exactly the correlation to expect from repeat flooding and persistent local siting practices. Set `cluster = ~countyfp` (2,245 clusters) on all claim-level specs. This is about what is defensible, not power: SEs barely move (1994–1999 cohorts, `geo^year_loss` 1.43–2.18 vs. `countyfp` 1.55–2.23). State clustering is the conservative fallback but has only 49 clusters and a visibly noisier variance estimate (1996 SE jumps to 3.46); if a referee asks for it, pair with a wild cluster bootstrap (`fwildclusterboot`) rather than the analytic SE. Two-way county + loss-year returned a non-positive-definite VCOV that fixest had to repair, and is redundant given `geo^year_loss` — do not use it.
- [ ] **Two-year construction bins as the default.** `BIN_CONSTR_YEAR` defaults to `1L` (`estimate-nfip.R:29`) and the Makefile calls the script with no arguments, so the paper is currently built on annual bins — but `paper.Rmd:144` already claims two-year binning. Set the default to `2L`. Free power, and it makes text and code agree: 1994 cohort goes from −1.96 (1.55), t=−1.27 to −3.22 (1.25), t=−2.58; 1996 from −4.28 (2.23) to −4.51 (1.67); 1998 from −6.10 (1.91) to −6.27 (1.69). Same monotone profile, five coefficients instead of eleven, all significant.
- [ ] **Extend the construction window back to 1983.** `MIN_YEAR_CONSTR` is `1988L` in `program/import/project-params.R`; set to `1983L`. Adds pre-reform vintage cohorts, which buys a much stronger parallel-trends test rather than precision on the treatment effects themselves. Claim counts are healthy back through the late 1970s (roughly 370–580 MH claims per construction year over 1977–1987), so the data are there.
  - Open question, not decided tonight: whether to also extend `MAX_YEAR_CONSTR` past 1999. Tested 1984–2003, which nearly doubles MH claims (5,389 → 9,296) at essentially the same static estimate (−3.88 → −4.16), but 1980–2005 attenuates to −3.03 (1.65). Decide which outcome the headline figure should show and make all three agree.

**Considered and deliberately not adopted.** Conditioning the main spec on `water_depth`, `elevated`, `sfha`, replacement cost, or coverage amounts. These are exactly the variables Table `tab:composition` shows moving after 1994 — they are mediators, not confounders (water depth is measured relative to the structure, so elevation mechanically lowers it). Adding them moves the static estimate from −3.88 to −3.02; that ~22% is the mediated share of the treatment effect being partialled out, not bias removed. The existing bounding argument in "Selection and Composition" is the stronger response to the composition concern, since the shifts all push expected payments up and the estimates decline anyway. If the `+ Controls` columns in `estimate-nfip.R` (`fmla_rob_b`, `fmla_rob_d`) stay, relabel them as a decomposition rather than a cleaner estimate — this constrains how Chunk F should be written up.

**Also worth knowing before leaning harder on levels.** 32% of claims have zero net building payment and the level distribution is severely right-skewed. `est_claim_pois` is already estimated at `estimate-nfip.R:265` but never reported; PPML and IHS give much weaker proportional effects (1999 cohort: OLS −5.88 (2.17); IHS −0.216 (0.108); PPML −0.077 (0.094)). The level effect is concentrated in the right tail — substantively defensible, and the right object for the NFIP fiscal calculation, but say so rather than letting a referee find it. Related power ideas not scoped here: permutation inference on the 1994 cutoff (with effectively one treated unit, an exact p-value from reassigning the threshold across vintages is cheap and persuasive), and `HonestDiD` sensitivity in place of resting on "flat pre-trends" — pre-period SEs of ~1.9 against effects of 4–6 mean the pre-test has limited power to detect violations that would matter.

## Chunk E — Housing-stock denominator and the take-up margin [agent; all inputs already on disk]

**Decision (2026-08-11): build this from public data, not CoreLogic.** CoreLogic assessment data does carry construction vintage, so a within-county vintage hedonic on 2023 assessed values is a legitimate design and is *not* ruled out — it is deferred on cost. What argues against it for the denominator specifically: chattel-titled MH are personal property and frequently absent from real-property assessment rolls, so its MH universe skews land-titled (the wrong subpopulation for this paper), and a 2023 snapshot conditions on surviving the very floods that generate the outcome.

**The outcome being fixed.** `estimate-nfip.R` currently computes `policies_ppermit = policies_n / permits_sf_n` (lines 170–172, 182–183, 351–357; dict entry line 74; already partly disabled). This is the wrong take-up margin for three reasons: the denominator is *single-family permits* and is applied to MH and site-built rows alike; BPS covers only permit-issuing jurisdictions, undercounting badly and non-randomly (see the diagnostic in DONE); and `databuild-nfip.R:306` spreads county permits uniformly across tracts, an arbitrary allocation. Replace it with `policies_per_home = policies_n / homes_n`, where `homes_n` is the stock of that housing type and vintage in that county.
