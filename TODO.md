# PROCESS

Work proceeds in delegated chunks (lettered below), each sized for one agent session and ending in a reviewable state: a branch with a focused diff, plus a short memo appended to `notes/LOG.md` stating what was done, what changed in outputs, what was verified, and open questions. Nothing merges to `main` without Colin reading the memo and diff; each merged chunk moves to DONE with the date and commit hash, so DONE doubles as an audit trail. Check-ins are weekly (~30 min): review the latest chunk, resolve open questions, and assign the next one. Two standing rules keep the project legible after time away: (1) no hard-coded numbers — every figure cited in `paper.Rmd` or `slides.tex` comes from a scalar CSV in `output/results/` written by an estimation script, and the full chain `derived/ -> program/ -> output/ -> paper.pdf` must rebuild via `make`; (2) a single spec sheet, `notes/specs.md`, records the exact estimating equation, sample restrictions, fixed effects, and clustering for every table and figure in the paper, and is updated in the same commit as any spec change. The paper text is checked against the spec sheet, not against memory.

Verification is built in rather than ad hoc. `program/tests/` holds fake-data tests run by `make test`: each estimator is applied to simulated data with known parameters (e.g., claims data with a built-in MH x post-1994 damage effect, common vintage effects, and geography-period shocks) and must recover the truth; the same harness demonstrates *why* the spec is right (e.g., that omitting common vintage effects biases the MH-vintage coefficients). Constructed denominators get the same treatment: any imputation must pass an exact adding-up test against its source totals and a fake-data test that recovers a known take-up gradient. Data-construction steps carry the standard sanity checks (uniqueness on intended IDs, cross-field consistency, missing-value accounting, counts validated against external benchmarks like Census 2000 MH counts and MHS shipments). Agent sessions run `make test` before opening a review; any red test blocks the merge. Review comments in `coarse-output/*_review.md` are the external checklist — each addressed comment gets flipped to `[Addressed]` in that file in the commit that addresses it.

Replace it with `policies_per_home = policies_n / homes_n`, where `homes_n` is the stock of that housing type and vintage in that county.
